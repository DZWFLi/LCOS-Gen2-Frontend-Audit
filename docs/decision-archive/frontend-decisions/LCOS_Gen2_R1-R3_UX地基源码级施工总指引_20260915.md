# 0. Codex 开工前先锁死的总纪律

## 0.1 权威顺序

发生冲突时按以下顺序处理：

```text
最新用户产品裁决 / 最终产品冻结
>
当前 HEAD exact source 的真实 owner / producer / consumer
>
已核施工卡 / 跨线程裁决
>
Figma 视觉规范
>
Donor UX / OSS primitive
>
旧文档 / 旧 Demo / 旧实现
```

说明：

- Figma 是 **视觉真值**，不是业务 truth。
- 当前源码说明“现在怎么实现”，不能覆盖更高层已冻结产品语义。
- Donor 只能解决“怎么做得成熟”，不能建立第二 owner。

## 0.2 R1–R3 绝对禁止

```text
× 新建第二 canvas/store/camera/history
× 新建第二 Project / Railway / Assembly truth
× drop 后再弹 taxonomy / destination picker
× Window 打开/resize 时自动移动 Camera
× Railway 再承担 Main / Context / Workflow 一级切换
× 把 UI optimistic state 当 canonical persistence
× 用 title / label / index 猜对象身份
× 用视觉状态推断 provider / receiver / Core 状态
× 为赶 Figma 截图而硬编码假数据 / 假 destination
× 单测绿就宣布 UX 完成
```

## 0.3 每一轮必须保持四层分离

```text
Canonical truth
  Core / Huabu

Interaction model
  React-free pure model

Host adapter / UI intent
  Huabu LCOS shell / Zustand ephemeral state

Visual body
  Figma component family / CSS / motion
```

任何 PR 如果把这四层揉进一个大 React 组件，停止施工，先拆 seam。

## 0.4 Done 的最低标准

每个 R 都必须同时通过：

```text
1. pure model unit tests
2. host/container tests
3. typecheck
4. production build
5. real browser pointer interaction
6. failure / stale / reconnect / narrow viewport path
7. Figma state review
8. git diff --check
```

不允许：

```text
“组件已存在”
“接口已定义”
“测试 mock 过”
```

被写成“完成”。

# R1｜Semantic Drop Foundation

## 1.1 本轮真正要解决的问题

当前已经有：

```text
apps/web-gen2/src/interaction/semanticDropMachine.ts
huabu/apps/web/src/lcos/lcosDropState.ts
huabu/apps/web/src/lcos/LcosDropPreview.tsx
```

现状是：

```text
payload acquired
→ pointer tracking
→ edge dwell
→ preview
→ committing state
```

但 **preview 后没有 canonical commit router**。

当前 `lcosDropState.ts::commitAt()` 只把状态切为：

```text
preview -> committing
```

并没有决定：

```text
这个 payload
拖到这个具体 target
到底调用哪个现有 owner
```

因此 R1 的目标不是扩写漂亮的 preview，而是建立：

> **Preview 与 Commit 使用完全同一个 resolved intent。**

用户看到“会发生什么”，release 后就只执行那一件事。

## 1.2 R1 canonical owners

R1 不拥有任何业务 truth。

必须复用：

```text
Canvas geometry / placement
→ Huabu

Artifact / Context / Workflow / Scene / Conversation truth
→ Local Core

Assembly apply
→ CoreAssemblyClient / existing Assembly apply route

Composer Reference draft
→ useLcosReferenceStore

Railway order
→ CoreRailwayClient
（注意：R1 的“drop 到 Railway destination”不是修改 Railway order）

Surface / Workspace identity
→ Core workspaces + existing shell/worksite nav
```

Drop 层只拥有：

```text
gesture
target hit
resolved intent
commit lifecycle
transient feedback
```

## 1.3 首先新增 Target Registry，但它不是第二 truth

建议新增目录：

```text
huabu/apps/web/src/lcos/drop/
```

建议新增：

```text
dropTargetRegistry.ts
dropIntentResolver.ts
dropCommitRouter.ts
dropTypes.ts
```

### `dropTypes.ts`

定义 UI 可命中的目标身份，不要把 DOM 节点本身当语义。

建议：

```ts
export type LcosDropTarget =
  | {
      readonly kind: 'canvas';
      readonly targetId: string;
      readonly canvasId: string;
      readonly surface: 'main' | 'context' | 'workflow';
      readonly workspaceId?: string;
      readonly label: string;
    }
  | {
      readonly kind: 'railway-destination';
      readonly targetId: string;
      readonly railwayKey: string;
      readonly workspaceId: string;
      readonly surface: 'main' | 'context' | 'workflow';
      readonly label: string;
    }
  | {
      readonly kind: 'composer-reference';
      readonly targetId: string;
      readonly label: string;
    };
```

第一轮只纳入 **已经有真实 owner / commit path** 的 target。

不要为了“矩阵完整”先加：

```text
collection membership
receiver
workflow extraction
archive
skill invocation
```

除非当前 exact source 已有真实 mutation owner。

Target Registry 只保存：

```text
targetId
semantic descriptor
live screen rect
priority
enabled/ineligible reason
```

它是：

```text
ephemeral hit-test registry
```

不是：

```text
drop destination persistence
```

DOM unmount 必须 unregister。

## 1.4 Pure machine 不再自己猜 left/bottom 就是 destination

当前：

```text
lcosDropState.ts
  left edge -> surface:left-dock
  bottom edge -> surface:bottom-dock
```

这只能作为早期 gesture experiment，不能继续成为最终 commit 语义。

修改原则：

### 保留

```text
tracking
dwell timing
carry zone
cancel distance
failed
```

### 调整

`semanticDropMachine.ts` 的 `DropDestination` 应从：

```ts
{
  kind: 'slot',
  anchor: 'left' | 'bottom',
  surface: string,
  place: SurfacePoint,
}
```

收敛成：

```ts
{
  readonly targetId: string;
  readonly previewPoint: SurfacePoint;
}
```

或等价的稳定 target identity + presentation point。

Pure machine 不应知道：

```text
AssemblyTargetRef
Core route
Railway write
React component
DOM selector
```

这些属于 host resolver。

## 1.5 建立唯一 `DropIntentResolver`

新增：

```text
huabu/apps/web/src/lcos/drop/dropIntentResolver.ts
```

职责：

```text
payload + target
→ ready intent
或
→ ineligible reason
```

建议类型：

```ts
type LcosResolvedDropIntent =
  | {
      status: 'ready';
      action: 'assembly-apply';
      sourceRef: AssemblySourceRefV1;
      targetRef: AssemblyTargetRefV1;
      previewLabel: string;
    }
  | {
      status: 'ready';
      action: 'composer-reference';
      reference: {
        entityType: string;
        entityId: string;
        displayLabel?: string;
      };
      previewLabel: string;
    }
  | {
      status: 'ineligible';
      reason: string;
      previewLabel: string;
    };
```

**Preview UI 和 commit router 都读取这个 exact intent。**

禁止：

```text
Preview 自己猜一句文案
Commit release 时再重新 resolve 一次另一套逻辑
```

否则 target 在拖动期间变化时会“看见 A，实际执行 B”。

## 1.6 第一阶段支持矩阵

### A. Existing LCOS object / Assembly item → 当前 Canvas / Workspace

语义：

```text
投放到哪里
=
Assembly apply 到那个 canonical target
```

复用：

```text
CoreAssemblyClient.apply()
AssemblySourceRefV1
AssemblyTargetRefV1
```

应把 `AssemblyBody.tsx` 当前局部的：

```text
assemblySourceRefOf()
```

抽成共享 pure helper，避免 Assembly button 与 Drop 各写一套 source mapping。

建议文件：

```text
huabu/apps/web/src/lcos/professional/assemblySourceRef.ts
```

Assembly 原按钮和 Drop router 共用它。

### B. object → Railway destination

这不是：

```text
“把 object 加到 Railway”
```

而是：

```text
Railway 暂时变成 destination map
→ drop 到具体 Worksite
→ apply object 到那个 Worksite
```

所以仍走：

```text
CoreAssemblyClient.apply()
```

绝不能调用：

```text
CoreRailwayClient.write()
```

`write()` 只属于 R3 reorder/manage。

### C. object → Composer Reference

走现有：

```text
useLcosReferenceStore.getState().addEntityToDraft(...)
```

Selection ≠ Reference 的冻结继续保持。

### D. file / text / url

只有当前真实 Capture / import owner 可以明确复用时才开放。

否则：

```text
ineligible
```

UI 如实说明：

```text
“此来源尚未接入当前目标”
```

不要临时写一套 local import。

## 1.7 Drop target 注册位置

### Canvas

在：

```text
CanvasHostBoundary.tsx
或其唯一 LCOS host wrapper
```

注册当前 canvas target。

Target identity 必须来自：

```text
projectId
canvasId
activeSurface
activeWorkspaceId
```

不能用 DOM id 猜。

### Railway

`LcosRailway.tsx`

正常状态不需要把整个 rail 变成 destination。

拖动开始时：

```text
Railway enters receive presentation
```

每个真实 destination item 注册：

```text
railway-destination
```

不可达 item 保持 ineligible，不隐藏事实。

### Composer

`LcosComposerHost.tsx`

只在 Composer visible 时注册：

```text
composer-reference
```

release 到正文编辑区域是否等价 Reference，要按已有设计卡，不能默认整块 Composer 都接受。

## 1.8 R1 state lifecycle

最终应该至少是：

```text
idle
→ tracking
→ dwell(targetId)
→ preview(resolvedIntent)
→ committing(transactionId, resolvedIntent)
→ success
→ idle
```

失败：

```text
committing
→ failed(reason, recoverable, targetId)
```

`committing` 必须冻结：

```text
payload
targetId
resolved intent
transactionId
```

避免异步返回后用“当前 hover target”完成另一个动作。

success 后业务 receipt 不保存在 drop store。

Drop store 只：

```text
complete transaction
→ transient success feedback
→ idle
```

canonical receipt 仍归原 owner。

## 1.9 R1 Figma 使用规则

UX 地基先完成。

然后才让 `LcosDropPreview.tsx` 对齐 Figma：

```text
tracking
dwell
eligible
hot
ineligible
committing
failed
```

Preview 必须贴 target body / slot，不再显示开发态：

```text
“放置 xxx → surface:left-dock”
```

视觉可以高保真，但不得新增第二 chooser。

Figma state 如果只有：

```text
receive
receive-hot
ineligible
```

则 reducer 状态映射到这几个 presentation state，不为 Figma 反造新的业务 state。

## 1.10 R1 Tests

```text
same target dwell -> preview
drift -> tracking
target changes -> old preview invalidated
commit freezes exact intent
failed transaction cannot silently become success
```

```text

object + railway destination -> same assembly-apply target
object + composer -> composer-reference
unsupported payload -> ineligible
```


```text

无 duplicate reference
失败后原 source 不消失

```

浏览器必须真实跑：

```text

```

## 2.3 把 `windows[]` 从“全局 tab 列表”升级成 instance + region




### safeRect 规则

Docked region：

```text

```

Floating region：

```text

```


# R3｜Railway Manipulation Foundation

## 3.1 R3 的核心边界

现在 Railway 的正确部分必须保护：

```text
SurfaceDock
=
Main / Context / Workflow 一级切换

Railway
=
durable destinations
```

当前 `LcosRailway.tsx` 已正确：

```text
CoreRailwayClient.read()
→ orderedRefs
→ projectRailwayDestinations()
→ onSelect navigate
```

而：

```text
CoreRailwayClient.write()
```

已经提供：

```text
orderedRefs
expectedVersion
```

所以 R3 不需要新 persistence。

R3 需要做的是：

> **把现有 durable order truth 接成可操作的 direct-manipulation rail。**

## 3.2 Railway 三类 interaction 必须完全分开

### A. Navigate

```text
click
→ destination activation
```

已有。

### B. Receive

```text
外部 object 正在拖动
→ Railway 进入 destination map
→ item 变成 eligible/ineligible target
→ drop
→ R1 DropCommitRouter
```

Receive **不改 Railway order**。

### C. Reorder / Manage

```text
拖 Railway item 自己
→ reorder
→ CoreRailwayClient.write()
```

这是唯一会改 order 的交互之一。

不要混。

## 3.3 R3 container 必须保存 raw Core order + version

当前 `LcosRailway.tsx` 只保存：

```text
destinations[]
```

这对 reorder 不够。

改成：

```ts
interface RailwayUiSnapshot {
  readonly order: ProjectViewRailOrderV0;
  readonly destinations: readonly RailwayDestinationProjection[];
}
```

保留：

```text
order.orderedRefs
order.version
```

所有 write：

```text
expectedVersion = 当前读到的 version
```

成功后：

```text
使用 server 返回的新 order
```

不要自己：

```text
version + 1
```

## 3.4 `RailwayDestinationProjection` 必须保留 source identity

当前 projection 有：

```text
kind
viewId
key
workspaceId
surface
```

R3 建议再明确：

```ts
readonly sourceRef: ProjectViewRailRefV0;
readonly sourceIndex: number;
```

或等价的稳定 mapping。

目的：

```text
UI reorder
→ 精确移动 raw ref
```

而不是：

```text
根据 label / workspaceId 重建一个 ref
```

## 3.5 Hidden legacy/root refs 的 reorder 算法必须安全

当前 projection 会过滤旧 root refs。

因此绝对不能：

```text
visible destinations reorder
→ write visible destinations only
```

否则会无意删除 hidden compatibility rows。

新增 pure helper，例如：

```text
apps/web-gen2/src/navigation/railwayOrder.ts
```

函数：

```ts
reorderRailwayRefV1(
  orderedRefs,
  movedKey,
  beforeKey | afterKey
): readonly ProjectViewRailRefV0[]
```

算法：

```text
从完整 raw orderedRefs 找 moved ref
从完整 raw orderedRefs 找 target ref
移动 exact raw ref
其它所有 ref 原顺序不变
```

hidden ref：

```text
保留
不丢
不自动 migrate
```

migration 是另一个职责。

## 3.6 Optimistic UX 与 Core CAS 的边界

允许：

```text
拖动时本地 neighbour shift / gap preview
```

release 后：

```text
optimistic visible order
→ CoreRailwayClient.write(expectedVersion)
```

成功：

```text
accept server returned order
```

409 / stale：

```text
rollback visual optimistic state
→ CoreRailwayClient.read()
→ re-project
→ 非阻塞反馈“Railway 已在别处更新”
```

禁止：

```text
自动拿新 version 重放用户旧 reorder
```

因为用户看到的邻接关系可能已变。

## 3.7 Railway Receive 完全复用 R1

当：

```text
useLcosDropStore.state != idle
```

Railway 可以进入：

```text
RECEIVE
```

item eligibility 来自：

```text
DropIntentResolver(payload, railwayTarget)
```

不是 Railway 自己判断：

```text
entityType === artifact ? eligible : ...
```

Presentation：

```text
RECEIVE
RECEIVE_ELIGIBLE
RECEIVE_HOT
INELIGIBLE
```

全部来自统一 resolver。

这样将来 Drop 规则改一次，Railway 不会有第二套。

## 3.8 Railway Peek

Peek 是：

```text
hover/dwell → compact concrete destination preview
```

它不是：

```text
modal chooser
```

第一轮如果没有真实 mini geometry producer：

```text
显示真实 identity + kind + count fallback（若真实有）
```

没有真实数据就不要画假 thumbnail。

Peek 不建立 destination truth，只展示 projection。

## 3.9 Overflow

当前 Railway 只是：

```text
maxHeight + overflowY:auto
```

R3 要先规范 UX contract，再做最终视觉。

规则：

```text
少量 items
→ rail hug content

超出 safeRect 可用高度
→ overflow state

active / receive-hot item
→ 永远保持可发现/可滚到

hover peek
→ 不撑开 rail 主轴
```

不要用：

```text
+N
```

冒充不可访问的目的地，除非 +N 本身能进入真实 overflow view。

## 3.10 Manage / Remove

低频管理：

```text
Huabu DropdownMenu / Popover
```

不要每个 item 常驻 3 个按钮。

Remove：

```text
从 orderedRefs 删除 exact ref
→ CoreRailwayClient.write(expectedVersion)
```

失败：

```text
UI rollback
```

Archive / Disconnect 只有当前 canonical owner 已存在时才能出现。

R3 不负责发明它们。

## 3.11 Receiver 不要在 R3 假实现

```text
不要为了 Figma 先塞一个假的 Receiver item
```

R3 只需让 container model 可扩展 species。

等 Receiver producer 真正进入 Current Source Census 后再接。

# 4. R1 → R2 → R3 的依赖关系

严格顺序：

```text

先固定：
payload
target
intent
commit owner

↓
R2
再固定：
viewport
window region
occupiedRects
safeRect

↓
R3
最后让 Railway 同时消费：
R1 的 drop intent
+
R2 的 safeRect
+
Core 的 order truth
```

这是为什么不能先做 Railway 漂亮 reorder：

Railway 最终既是：

```text
导航
```

又是：

```text
Semantic Drop destination map
```

还必须：

```text
避让 Professional Window
```

R1/R2 不稳定时，R3 视觉越精致，返工面积越大。

# 5. 给 Codex 的每轮执行 SOP

```text
caller
```

```text

```

不能靠本文里的旧行号继续猜。

## Step 2｜写一页 Change Boundary

施工前先列：

```text

CHANGE

```

确认没有建立第二 owner。

## Step 3｜先 pure model

```text

```

再接 React。

## Step 5｜Figma high-fidelity

```text
body geometry
tokens
state styling
motion
reduced motion
LOD
```

禁止 Figma pass 偷偷新建语义。

## Step 6｜真实浏览器

每个 R 至少保存：

```text
before
during
after
failure
narrow viewport
```

的截图 / trace / console evidence。

## Step 7｜自检后才进入下一 R

必须逐项回答：

```text
Canonical truth 是否仍唯一？
是否还有 mock-only path？
是否还有 preview != commit？
是否还有 UI state 冒充 persistence？
是否存在 stale / race？
是否存在 reload 后消失却宣称 durable？
是否真实浏览器通过？
```

任一为 YES：

```text
STOP
补齐本 R
```

不能写 Handoff 把债务塞到下一轮。
