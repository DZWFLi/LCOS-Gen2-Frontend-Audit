## 结论

问题确实很大，但已经不是一团雾。当前可以分成四层：

1. **身份串线**：集合、Context、Workflow、Workspace 曾共用同一 Atlas 文件夹外观。这就是“左下按钮成了啥、打开后像功能杂烩页”的根因。主画布集合入口现在只认 canonical Collection，现场导航留在 Context。
2. **壳层强、功能弱**：HUD 已有统一材质，但 Railway、Drop、Color Pin 成员、浮游标、Glyth 状态机还没有形成同一套可学习的动作语言。
3. **组件在，真实链没验完**：Collection 成员接口、Rail 排序持久化、Drop resolver / receipt、Glyth 持久上下文都有源码，但“用户动作→真实回执→重载后仍在”没有全部跑完。
4. **特殊视图还未全部长出自己的脸**：Context Atlas 和 Workflow 轻预览已改对语义，但根 Context / Workflow 仍偏 Main 画布换激活态；真正的关系 / 证据 / 时间与阶段 / 执行 / 结果还没成为整个画面的主角。

## 仍然是产品缺口

### P0

1. **Railway 用户添加链与稳定目的地身份**。当前项目 0 目的地时隐藏是对的，但用户从哪里“加入 Railway”以及 reload 后怎么稳定恢复，尚未闭环。
2. **Drop 六类 Receiver 的统一可见语言**。代码有路由，画面没有稳定地教会用户“哪里可以放、放了会怎样”。
3. **Context / Workflow 根现场强视图**。Atlas / 手牌已改对局部语义，根页仍然不足以一眼认出“理解现场”和“行动现场”。
4. **Portal 投递生命周期**。已有预览 / 打开既有目标，但创建、取消、unknown / failure、目标缺失、返来来源没有完整 production owner 链；所以 Arc 里不再假造提交。
5. **Run / waiting / recovery 的真 provider 闭环**。组件和 Core caller 存在，但网页与真实 provider 的排队、运行、等待输入、错误、中止、恢复尚未全验。

### P1

1. **Glyth 本体状态机弱**：深度会话窗可用，但“正在理解 / 等待 / 运行 / 需要用户 / 完成 / 失败”应先在 Glyth 本体上成为第一视觉。
2. **空间导航展开态太重**：默认单按钮没问题，展开后的预览、缩放、锁定、网格、连线、小地图一次全出，挡视线。
3. **Color Pin 成员身份弱**：顶部灵动岛逻辑正确，展开后仍是通用行列表和 location 图标，没有节点物种 / 缩略 / 高饱和轮廓。
4. **浮游标终态还是占位箭头**：定位、密集排布和 arrival 路径在，最终 donor 形态、物种身份和边缘色彩弥散还没收定。
5. **Assembly 仍偏卡片后台**：窗口、检索、来源 tab 可保留；真实媒体占比、近场预览、瀑布流和不同物种的面型还需加强。
6. **连线默认隐藏是对的，选中态仍是 Huabu 原线型**：线、端点、标签及出现 / 退场要收成 TapNow / Figma 近场关系语言。
7. **多选真实鼠标链未录证**：自动化没能得到两个选中节点，Playwright 环境又缺 Chromium shell，因此当前不宣称坏，也不宣称通过。
