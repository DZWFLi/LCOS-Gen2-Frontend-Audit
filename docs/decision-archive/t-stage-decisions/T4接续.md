这轮最重要的施工结论有几个。

第一，Assembly 根本不需要再造“统一资产后台”。Current Core 已经存在四路成熟 source：

PROJECT

→ WarehouseService


CAPTURE

→ system/global Capture Space


SOURCES

→ Project Resources


SKILLS

→ layered Skill Catalog

其中 Capture 的源码注释甚至明确写着它是“系统级暂存画布，不属于任何 Project”，所以 Assembly 的 Capture 页应该是读取全局暂存区，再 Apply 到当前 Project/target，而不是每个 Project 再复制一份 Capture。

第二，AssemblyApply 本身继续 KEEP，不重写。 Current service 已经按照 sourceRef + targetRef 路由到既有 canonical mutation，而且 Capture 的物化是幂等的。Capture 已经进入过这个 Project 时，会返回 skipped / already-member，不会重复造 Artifact；Capture → Surface 也是先物化一次，再进入目标，第二步失败后重试会复用第一次结果。

这意味着 UI 绝对不能自己搞“失败以后把 Artifact 删回去”的假回滚。Core 已经替我们把幂等关系想好了，我们就别热心地帮它弄坏。

第三，这轮把一个很容易漏掉的问题钉死了：HTTP 200 不等于 Assembly 全部成功。

Current contract 是逐 item：

status:

applied

skipped

failed


channel:

workspace-membership

presentation-membership

relation

capture-materialize

already-member

unsupported

error

而整个结果还有：

allApplied

results[]

changeSetId?

也就是说三件东西：

2 applied

1 failed

完全可能是一个正常的 HTTP 200 response。

所以 C1-3 已经把 UI 状态锁成：

APPLIED

SKIPPED_ALREADY_MEMBER

PARTIAL

FAILED

UNSUPPORTED

不是传统的：

success toast

error toast

两种人格。

第四，web-gen2 不需要扩成 mega facade，也不用改 HttpClient。 Current HttpClient + coreRequest 已经支持 JSON、AbortSignal、统一 Core envelope/error normalization，Assembly 这一轮所有必要 route 都是普通 JSON read/apply，直接复用即可。
