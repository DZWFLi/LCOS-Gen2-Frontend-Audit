# 右键管理UX：先纠正对象身份错接

日期：2026-09-27。仅一名 Luna / medium 子代理只读核原件，主代理施工与浏览器验证。没有恢复旧高推理子代理。

## 本轮确证的问题

真实Glyth右键菜单竟出现自动高度、转为文本、强调色、打开大视图。根因是 `buildLcosNodeCommands` 根据宿主 `nodeType=note` 选择原生笔记能力；而Glyth的真实身份是Conversation。原生转换调用convertNodeType，旧大视图调用previewWorkspace，不属于Glyth的会话呈现链。

另一个确证错接：移动到其它现场实际调用Huabu MoveSelectionModal，后者只执行物理画布节点移动，不迁移LCOS Core绑定。给已绑定对象显示可执行的“移动”会误导用户。

## 已修与未修明确分开

- Glyth不再继承笔记类型转换、自动高度、强调色和旧笔记大视图；保留会话动作、引用、颜色组、实际尺寸和相机动作。原生未绑定笔记能力不删。
- 已绑定对象的跨现场移动暂明确不可用；原生未绑定对象移动仍可用。这是堵住错误派发，不是完成跨现场移动。仍需正确的绑定/投影迁移链。
- 右键／More共用同一命令模型，因此同步纠正，无第二套命令表。
- **没有声称完整右键UX完成**：各物种完整管理动作、复制/移除语义、菜单焦点与多选等还要逐项对原件与实际owner。没有擅自新增“空白右键创建”。
