# DZ Apple × Ice Works · Candy Signal v3

日期：2026-09-17

本次交付：沿用 SeedMotion 的完整作品集，恢复红色不透明糖衣苹果，修正手与小苹果的视觉对位，并将用户提供的图形参考落实到内腔、入口、文字、读取状态及滚动结尾。不是另做一个 Demo，也不是直接复制 Marathon 的游戏界面。

## 1. 本轮先纠正了什么

上一版 `MarathonPolish_v2` 确实有文件，但回复只有代码块内的磁盘路径，没有提供可点击下载链接。更重要的是，上一版只有少量材质和位置参数修改，没有完成参考图、视频与实际页面之间的核对。

浏览器里还复现了实质问题：虽然 `createResinMaterial()` 指定了红色，`portal.js` 的逐帧更新仍用白色覆盖材质，并再次覆盖粗糙度。外壳去掉照片纹理之后，最终呈现为白色磨砂苹果，而不是所宣称的红色苹果。构建与原有单元测试不会自动发现这种视觉错误。

本轮移除了这两处互相冲突的外观赋值，让颜色与粗糙度由材质配置统一控制。浏览器实测包括正常开场、动画后、重置后，确认红色不会再次被覆盖。

### 代码清单并不等于源码事实

包内实现清单将三个入口描述为玻璃三维几何物件，但当前 SeedMotion 的真实执行路径已经不是这样：

- `src/entry/objects.js` 并未挂入当前主渲染流程。
- 实际入口来自 `assets/entries/*.webp`，由 `src/ring/engine.js` 和 `src/ring/shaders.js` 绘制到原有 SDF 场中。
- 因此本轮修改的是实际入口图集和该场中的激活事件，没有继续改一个不生效的 Three.js 物件模块。

包内旧手素材没有替换掉用户后来提供的 `Hands (30).png`。保留新手，避免为了换皮倒退到旧抠图。

## 3. 实际修改

### 3.1 大苹果恢复红色糖衣方向

保留原来的连续曲面、边缘、厚度与开合形态。恢复饱满的红色，不再使用外壳的果皮照片贴图，也不走白色磨砂或全透明玻璃方向。

外壳采用不透明材质、糖衣高光和侧向柔光；果梗也改为同一红色材质家族，避免原来的深黑棕色块割裂主体。小真实苹果及后续四段吃苹果图片未替换。

这不是对早期版本的像素级复刻，而是在当前已认可形体上恢复用户更喜欢的外观方向。

实现：`src/apple/material.js`、`src/apple/portal.js`。

### 3.2 手向左，小苹果路线不动

只将手部平面顶点向左移动 0.14 个局部单位。原来的手掌定位函数、手部世界变换和 `seedTransfer` 保持不变。

这样移动的是可见手素材，而不是连着小苹果一起搬走。小苹果仍由原掌心定位与转移函数驱动，后续入口、项目浏览、吃苹果和 Callback 复用同一 mesh。

手仍使用用户提供的新拼贴素材，保留 alpha、深度测试和腕部入腔遮挡。只加了一个很轻的局部注册标记，没有重新生成人手，也没有改成覆盖网页的 DOM 贴纸。

实现：`src/apple/hand.js`。

### 3.3 内腔：低对比等高线加少量印刷信息

保留原迷雾等高线。两半内腔只增补少量注册十字、小字、分段短轨和一个很小的信号色片。

这些内容进入已有内腔 shader，而不是另外浮在手上的装饰层。左内腔单独处理镜像，避免打开后文字反向。新纹理也纳入原有预热与清理路径。

实现：`src/apple/field.js`、`src/apple/portal.js`。

### 3.4 三入口：换表面，不换布局

继续采用原有 Coolshapes 轮廓，不重新堆球、环或多面体。三张入口图集保留原 alpha 距离场，只重整内部颜色和图形：局部编号、很小的身份字、注册十字、短轨及低密度点阵。

当前入口切换或悬停时，只有目标对象产生一次短促扫过。这个事件在原 SDF shader、原帧循环中完成，没有新增一个 renderer、全屏粒子层或独立动画循环。

大尺度离屏构图、左侧局部苹果、一次一个完整入口、惯性、吸附与原关系线继续保留。

实现：`assets/entries/{projects,about,workflow}.webp`、`src/ring/engine.js`、`src/ring/shaders.js`。

### 3.5 文字、读取与状态不再各说各话

- 原标题按行显影保留，调整为短距离裁切与轻微模糊收敛，不使用长时间乱码。
- 当前章节名随切换重新显影；出现后安静可读。
- 右上微型索引来自真实当前章节或项目，三个标记对应实际章节状态，不是随便填的坐标。
- Composer 的九点标记对应 `ACQUIRE → INDEX → READY` 三种实际 UI 状态；小窗依然从读取态展开为正文，不额外增加等待。
- `READY` 后点阵停止循环，四段正文和证据材料按原逻辑出现。
- 项目墙卡片只在悬停或键盘聚焦时出现少量编号、类型与角标。

实现：`src/App.js`、`src/styles/site.css`、`src/archive/engine.js`。

### 3.6 Callback 保持同场滚动

原来两张本人照片、接苹果核、抛下、砸头、粒子与 DZ 的连续滚动叙事不改。

自我介绍保留原文本，只增补细小色片和序号。撞击的短线根据实际头部坐标出现，不使用整屏闪烁。右上状态标记在照片在场期间退让，等照片离场、最终完成后才恢复，避免文字叠在人脸上。

实现：`src/App.js`、`src/styles/site.css`、`src/world.js`。核心运动仍由原 `src/outro/choreography.js` 驱动。

## 6. 使用与内容替换

直接保存 `DZ_Apple_IceWorks_CandySignal_v3.html`，在支持 WebGL2 的浏览器中打开。无需 npm、CDN 或远程服务。

开场可点击“打开这个念头”或向左拖苹果。入口支持滚轮、拖动与键盘。章节任选；完成后剩余入口会减少。详情按 Esc 或关闭按钮返回。最后一章结束后继续滚动可推进 Callback，反向滚动可倒回。

项目名称、文字、示意封面和证据路径仍集中在 `content.json`。本轮没有代替用户编造新的正式项目成果。

源码重建：

```sh
npm run check
npm test
npm run build
npm start
```

本地依赖随源码保留。`npm start` 监听本机 4173 端口；构建后的自包含文件位于 `dist/DZ_Apple_IceWorks_Final.html`。

源码包的 `verification/` 保存本轮成功运行的 JSON、日志、截图和检查脚本。浏览器检查需另外具备 Python Playwright、Chromium 与 Linux Xvfb；它不是网页运行依赖。
