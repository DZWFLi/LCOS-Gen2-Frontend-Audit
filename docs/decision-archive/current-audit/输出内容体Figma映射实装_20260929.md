# 受管图像输出复用 Main 图像身体（2026-09-29）

## 结论

受管产出仍保留 `output` 的外层 family / Run 来源语义；但有权威图像 MIME 或 `artifactKind` 时，内容身体不再落进通用白卡，而是复用既有、Figma 绑定的图像身体。未知 payload 仍回退“运行结果”generic 身份，不猜媒体类别。图片、文档、文本、音频、视频、网页都沿用现存专属分派；本次没有新增卡片或材料形态。

## 改动

`huabu/apps/web/src/lcos/nodes/source/SourceMorphology.tsx` 对 `family === 'output'` 单独读取既有 `resolveVisualFamily`，输入限定为 `entityType: 'artifact'` 加真实 `mimeType / artifactKind`（不传 managed/sourceRunId，避免 output 语义短路）。若可识别，就用对应 morphology；否则保留 `output` fallback。

生产 caller `LcosSpeciesBody` 已把 `descriptor.mimeType`、`descriptor.artifactKind`、解析出的真实 `mediaSrc` 传入 `LcosSpeciesBodyContent → SourceMorphology`。外层 `data-lcos-visual-family="output"` 仍是产出身份；`descriptor.sourceRunId` 仍传给 body，原有“生成结果”来源提示继续由真实 sourceRunId 驱动。内容 family 只决定真实 payload 长什么样，不覆盖归属事实。
