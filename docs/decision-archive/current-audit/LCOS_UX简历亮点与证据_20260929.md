## 1. 同一项目的三种工作现场

- 问题：素材、上下文组织和工作流操作分散，切换时容易失去对象身份和原来的工作位置。
- 设计选择：主画布、上下文、工作流共用项目材料与对象身份，同时各自保留相机、选择和布局；Context 组织上下文，Workflow 区分预览、进入现场和取用。
- 工作路径：在项目内组织材料→查看关联现场→进入真实子现场→返回来源；取用工作流材料不会自动执行。
- 状态：已设计；三现场与部分真实入口已实现。Workflow workspace 进入已接，不能说完全缺失；region/origin 精确定位、完整真实 child 路径未全面验收。最新工作流预览轻幕有浏览器样本证明，不能扩大为三现场全链验收。
- 简历表述：设计共享项目上下文的主画布、上下文与工作流三现场，区分预览、进入与取用，保留跨现场操作的空间连续性。
- 证据：Figma 5388:96、5388:21602、5388:22998；T3_T4_UX原件对照.md 第17–19项；Context_Workflow_UX小批修复_20260929.md。源码 surfaces/workflow/WorkflowCardPool.tsx、WorkflowWorksite.tsx。

## 2. Glyth 续工与继承范围的显式选择

- 问题：继续旧对话、建立新对话和分支容易被混为一谈，用户不清楚历史、材料和工作目录究竟继承了什么。
- 设计选择：明确续用原会话、精选上下文新建、空白新建、完整历史分支四种模式；历史、引用和工作目录独立表达。先预览继承范围，再确认提交。
- 工作路径：从 Glyth/Composer 进入续工→选择模式→查看材料与继承范围→确认；失败时核对或恢复原请求，避免重复创建。
- 状态：已设计；能力判断、请求与恢复接线已实现。最新 2×2 图标选择替代下拉已写入修复区，9项定向测试通过，尚未浏览器视觉验收；外部 provider 全链不保证全部打通。图标选择改动也不代表完整 Glyth 空间分支形态已经完成。
- 简历表述：梳理 AI 会话续工与分支的四类继承路径，通过近场预览明确历史和材料范围，并设计失败恢复与重复提交防护。
- 证据：Figma 5352:1958、5352:1969；T3_T4_Glyth续工与Composer继承入口UX_20260929.md；原T7 GEN2_T7_Glyth续工_AgentAdapter源码蓝图施工正本_V2_20260911.md §9/§12.3；源码 professional/ConversationContinuationControls.tsx。

## 3. 同一拖放手势，明确区分长期上下文与单次引用

- 问题：把材料交给 AI 时，用户难以判断它是进入会话长期上下文，还是只参与当前一次发送。
- 设计选择：投放到 Glyth 本体表示持久会话上下文；投放到 Composer 引用槽表示当前草稿引用。展示当前接收者、引用内容和失败原因，不用一个泛化“添加”按钮掩盖不同后果。
- 工作路径：选材料→拖到具体目标→查看引用/接收反馈→发送或继续编辑；续工精选材料先展示提交快照。
- 状态：已设计；本体持久读取与后续发送合并链已修，Composer 草稿引用与定向检查已有。仍缺所有材料类型、外部接收者与通用 Drop 目标矩阵的完整实测。正式 Collection 成员 Drop 尚未接通，不能写“任意对象可投放任意目标”。
- 简历表述：定义面向 AI 协作的语义拖放，区分会话持久上下文与单次草稿引用，通过接收目标和材料预览降低操作歧义。
- 证据：T1-T7_UX总对照与施工顺序_20260927.md；T3_T4_UX原件对照.md 第9项；修复区 nodes/GlythNodeBody.tsx、composer/LcosComposerHost.tsx、ui/nearfield/ComposerReferenceStrip.tsx。

## 4. 面向大型画布的集合与空间导航

- 问题：内容一多，当前视野之外的对象难以找回；持续展开的导航工具又占用创作空间。
- 设计选择：区分集合组织、Color Pin 分组、画外浮标定位和 Railway 快速进入；导航随内容增长，尽量保持紧凑。集合兼顾远中近层级与成员组织，而非统一成普通卡片。
- 工作路径：标记/组织对象→通过浮标找回画外目标→定位→返回工作现场；多组归属通过提示说明，避免误认为只属于一个组。
- 状态：已设计；基础身份定位与导航呈现已实现，最新多组提示有3项定向检查。正式 Collection canonical 成员链未完成，已获授权但暂后置；密集碰撞、自定义形状和完整导航回程未全面验收。不能写“完整集合管理已交付”。
- 简历表述：设计结合分组标记、画外定位与侧边快捷入口的空间导航，减少大型画布中对象查找与工具遮挡的冲突。
- 证据：Figma 5388:27696及13页集合专项；Luna_T1_T2_UX修复回传_20260929.md；集合与Drop_实施核对_20260929.md；源码 navigation/LcosPersistentLocatorOverlay.tsx、ColorPinHud.tsx、LcosRailway.tsx。

## 5. 围绕对象的近场操作与一致命令语义

- 问题：通用右键菜单把不适用的动作暴露给不同对象；多选、键盘和单选入口规则不一致，会导致误操作。
- 设计选择：Arc 包住节点右上角，主动作就近呈现，省略号承接次级菜单；动作由对象身份决定。单选、多选和快捷键复用身份保护，而非只改视觉样式。
- 工作路径：选中对象→看到对应命令→就地操作；多选涉及绑定对象时明确说明限制，不静默只操作一部分对象。
- 状态：已设计；Glyth 误带笔记命令已修并有浏览器记录。绑定对象多选删除/移动保护已实现，并通过真实触控多选样本检查。跨现场移动能力、全物种菜单与全部键盘路径尚未全验收。
- 简历表述：设计对象感知的近场命令体系，统一右键、Arc 与多选入口的动作边界，避免错误命令和部分执行造成的信息损失。
- 证据：右键UX_对象身份错接修复_20260927.md；UX逐项修复_施工记录_20260929.md；源码 navigation/LcosActionArc.tsx、LcosMultiSelectToolbar.tsx。

## 6. 轻量输入与可移动专业窗口分工

- 问题：聊天、素材库和阅读器挤占画布，或每种反馈都打开大面板，打断创作节奏。
- 设计选择：Composer 承担对象附近的输入与引用；装配仓库以素材浏览和取用为主；Reader 与复杂工作由可移动/缩放的专业窗口承接。轻反馈留在对象附近，不让装配页承担所有会话工作。
- 工作路径：在近场快速输入→需要深入时打开专业窗口→阅读/取用→回到原对象；归档列表跟随外部材料状态变化。
- 状态：已设计；专业窗口移动/缩放、Reader 指定版本与回来源等已有实现记录。多窗口 dock/split/恢复未全量浏览器验收。归档窗口外部归档/恢复自动更新有真实浏览器样本。语音虽有接线与定向检查，尚未真实麦克风/provider验收，不建议作为简历已完成亮点。
- 简历表述：划分近场输入、素材装配与专业阅读的操作层级，以可移动工作窗口保留画布视野和创作连续性。
- 证据：Figma 5388:27165、5388:27411，Composer 5283:890；T3_T4_UX原件对照.md 第20–23项；T6_ArchiveBody外部变更刷新修复_20260929.md；源码 professional/ProfessionalWindowStage.tsx、AssemblyBody.tsx、ArtifactReaderBody.tsx。

## README 的产品叙事遗漏

本次读取主仓 E:\OS开发\LCOS_GEN2\README.md。远端 origin 为 https://github.com/DZWFLi/LCOS_Gen2.git；经本地代理用 GitHub CLI 读取远端 README 返回404，因此无法确认远端最新版与本地完全一致，不能把以下结论冒充远端核验。

本地 README 主要讲 truth、kernel、owner、production caller 和施工账本，对开发者有用，但对招聘方缺少：

1. 谁在使用、要完成什么：面向创意人士，让项目文件成为与多个 Agent 协作的共享上下文。
2. 一条具体创作故事：整理图文材料→提供上下文→生成/讨论→取用结果→续工；现在只有架构调用链。
3. 三现场对用户的价值：Main/Context/Workflow 写成语义现场，却没有解释对应任务、切换与回程。
4. 核心交互差异：持久投放与单次引用、继承模式、对象近场命令、画外导航没有成为产品亮点。
5. 可视证据：缺全景、局部操作截图/视频，以及它们对应的设计或实现阶段。
6. 诚实的完成度：没有区分已设计、已实现、样本验收、未接通和修复分支未合并。
