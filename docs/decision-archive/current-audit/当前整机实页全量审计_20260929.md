## 结论

当前最大问题不是“某个图标丑”，而是四套语义在壳层串线：

1. **Collection、Context、Workflow、Workspace 曾被同一个 Atlas 文件夹外观承载。** 实页首次检查时 Main 的“6 个集合”实际混入 `施工主线`、`Context · 理解现场`、`Workflow · 行动现场`。这会让用户无法判断自己是在管理对象集合，还是切换工作现场。
2. **Context / Workflow 还没有形成自己的强视图。** 两页目前基本是 Main 画布复用，靠底部按钮激活态和一个局部浮层区分。Context 仍露出 Huabu 原生 `W 200 / Font 16` 工具条；Workflow 的内容组织、任务态和进程态没有成为画面主角。
3. **选中、右键和更多命令仍是 Huabu/SaaS 式长菜单。** 主动作没有稳定落在紧贴节点的 Arc / 近场图标层，次级动作又扩成超过一屏的滚动表单，既挡画布也破坏 LCOS 的“对象直接操作”语言。
4. **Railway 在当前真实项目里没有可见目的地。** 组件和排序写入链存在；0 目的地时收缩符合“添加后才生长”的既定规则，所以不能仅凭不可见判错。真正要追的是：这个已有项目为什么没有预期目的地、用户添加链是否可达、稳定目的地身份是否闭合。
5. **Drop、浮游标、Color Pin、Glyth 各自有局部实现，但还没有组成同一套动作语言。** Drop 目标缺少常态预告；Color Pin 已有灵动栏雏形，但展开层仍像普通列表；Glyth 又落成一块大白色专业窗口，状态机与本体身份被表单信息盖住。

这不是推倒重来。搜索灵动栏、项目主页、Reader、窗口几何和三 Surface 真实路由可以保留。当前要做的是把 **Gen1 的用户动作骨架、T1–T7 的语义裁决、Figma 的空间层级**重新接回生产 caller。

## 严重级问题与源码位置

### P0-1：Context / Workflow 没有成为独立强视图

- **页面 / 状态**：`/context`、`/workflow` 默认态。
- **为什么成立**：两页直接复用同一批节点和相近相机画面；Context 露出 Huabu 原生文字编辑条，Workflow 没有用任务、阶段、执行、结果建立主层级。
- **源码**：
  - `huabu/apps/web/src/lcos/surfaces/context/ContextWorksite.tsx`
  - `huabu/apps/web/src/lcos/surfaces/context/ContextAtlasStage.tsx`
  - `huabu/apps/web/src/lcos/surfaces/workflow/WorkflowWorksite.tsx`
  - `huabu/apps/web/src/lcos/surfaces/workflow/WorkflowCardPool.tsx`
  - `huabu/apps/web/src/lcos/ui/context/*`
  - `huabu/apps/web/src/lcos/ui/workflow/*`
- **建议**：修改。保留同一 Canvas kernel 和现有路由 owner；Context 补回 Atlas / 关系 / 证据 / 时间的强呈现，Workflow 补回任务卡池 / 阶段 / 执行 / 结果的强呈现。不要创建第二 Canvas。
- **补证**：需要。按昨晚 Context / Workflow HTML 和对应 MD 做逐状态实页复验。

### P0-2：Railway 目的地来源与添加闭环未被实页证明

- **页面 / 状态**：三个 Surface 的当前 fixture；左侧没有 Railway 目的地。
- **为什么成立**：`LcosRailwayView` 在 `items.length === 0` 时高度和 padding 都归零，这本身符合“添加后才生长”。缺口是当前项目没有任何预期目的地，且本轮没有从既有对象完成“加入 Railway → 左栏生长 → Peek / Receive → 重排 / 移除 / reload”的实页证据；稳定 destination ontology 也仍需闭合。
- **源码**：
  - `huabu/apps/web/src/lcos/shell/LcosRailway.tsx`
  - `huabu/apps/web/src/lcos/ui/families/LcosRailwayView.tsx`
  - `huabu/apps/web/src/lcos/navigation/railwayProjection.ts`
- **建议**：先核真实添加入口和目的地身份，再决定是否需要零态提示；不要为了“看见 Railway”硬塞一个常驻底座。底部 Surface Dock 继续常驻，Railway 只在有目的地后纵向生长。
- **补证**：需要。新增 / 重排 / 移除 / reload / Receive 完整动作链。

### P0-3：节点右键与省略号菜单破坏近场操作模型（本轮已收口，待窄屏复验）

- **页面 / 状态**：任意节点选中、右键、更多命令。
- **为什么成立**：右键层和省略号层把关系、编辑、尺寸、颜色、空间、Portal 全部平铺成滚动表单；常用命令没有在节点右上 Arc / 近场中稳定出现。
- **源码**：
  - `huabu/apps/web/src/lcos/navigation/LcosActionArc.tsx`
  - `apps/web-gen2/src/interaction/nodeCommandModel.ts`
  - `huabu/apps/web/src/components/Common/CanvasFloatingPopover.tsx`
  - `huabu/apps/web/src/components/Common/DropdownMenu.tsx`
- **现状**：右键已回到同一 Arc owner；More 首层已改为短动作网格；尺寸、强调色已拆为相邻二级 inspector。
- **补证**：桌面实页通过；仍需按文本、图像、Glyth、Collection、Portal、Workflow 六种物种与窄屏分别验。

### P0-4：Drop 仍缺跨目标统一的可见动作语言

- **页面 / 状态**：Collection / Railway / Portal / Glyth / Composer / 空白画布。
- **为什么成立**：源码已有 resolver、registry、preview、receipt 和若干真实 commit；但当前首屏没有可学习的 Drop affordance，本轮未获得“拖起→目标高亮→预览→提交 / 取消→回执”的整机证据。Railway 又因零项消失，进一步切断 Receiver。
- **源码**：
  - `huabu/apps/web/src/lcos/drop/*`
  - `huabu/apps/web/src/lcos/LcosDropPreview.tsx`
  - `huabu/apps/web/src/lcos/lcosDropState.ts`
  - `apps/web-gen2/src/interaction/semanticDropMachine.ts`
- **建议**：修改并实测。共用同一 Drop 状态机和边缘弥散反馈；不同 Receiver 只替换目标图形和文案，不再各造一套弹窗。
- **补证**：必须有短录屏，静态截图不足以说明手感。

## 高优先问题

### P1-1：Workflow 手牌的空间和动作层级不成立

- 单卡居中、左侧大量空白、动作在无障碍树里没有清晰按钮身份。
- 应保留“卡牌 / 瀑布流”而减少面板文字；预览、取用、进入必须视觉分级。
- 源码：`WorkflowCardPool.tsx`、`WorkflowHandView.tsx`、`WorkflowTaskCardView.tsx`、`workflow-hand.css`。
- **本轮后状态**：轻预览已把“加入草稿”与“打开现场”拆开，并只显示真实 read model 事实；瀑布流高密度、filter / recent 和多卡运动层次仍未完成。

### P1-2：Glyth 变成通用专业窗口，状态机被表单盖住

- 当前窗口可以工作，但“正在理解 / 等待 / 运行 / 需要用户 / 完成 / 失败”没有通过 Glyth 本体形态成为第一视觉。
- 会话材料投放应通过 Assembly、Composer 引用、Arc 和 Glyth 本体 Drop 被吸收；大窗只在深入会话时出现。
- 源码：`GlythNodeBody.tsx`、`ConversationWorkViewBody.tsx`、`glythBodyLayout.ts`、`glythPresentation.ts`。

### P1-3：空间导航展开态太重

- 当前展开层一次性放出预览、缩放、锁定、网格、连线、小地图和适合画面，遮挡左下大片内容。
- 默认保持单图标；一次点击展开紧凑横 / 竖列；小地图再作为独立二级展开，不要常驻大空框。
- 源码：`LcosSpatialNavigator.tsx`、`LcosSpatialNavigatorView.tsx`、`lcos-hud-presentation.css`。

### P1-4：Color Pin 机制成立，视觉身份仍不够

- 搜索 / Pin 共用灵动栏的伸缩方向正确。
- 成员展开仍是普通行列表，通用 location 图标不表达节点种类；需要高饱和小图形、目标缩略或物种轮廓。
- 源码：`ColorPinHud.tsx`、`ColorPinMemberPreview.tsx`、`projectedPinTargets.ts`、`NodeColorPinMarkers.tsx`。

### P1-5：Assembly 仍偏卡片后台

- 现有窗口生命周期、搜索、来源 tab 可以保留。
- 材料区要提高图片 / 文档真实预览占比，隐藏原始 hash / 元数据，减少“暂无预览”；现场 / workflow / conversation 不应与普通项目材料用完全相同卡面。
- 源码：`AssemblyBody.tsx`、`AssemblyMasonryView.tsx`、`AssemblyMaterialView.tsx`、`professional-assembly.css`。

### P1-6：连线已默认隐藏，但选中态仍带 Huabu 原线型

- 空间导航显示“显示连线 = false”，但选中节点仍显示连接线和 `references` 标签。
- “只在相关对象选中时显线”可以保留；线型、端点、标签和出现 / 退场应换成 TapNow / Figma 近场关系语言。
- 源码：`connectionViewEdges.ts`、`LcosEdgeArc.tsx`、Canvas edge renderer。
